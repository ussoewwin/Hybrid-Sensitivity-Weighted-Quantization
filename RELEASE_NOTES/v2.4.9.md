## Overview

v2.4.9 turns the backdoor check into an audit that can be read, repeated and contradicted: one written
operating procedure, its own tools and gates, a record for every number, and one verdict report per
published file. Twelve files now carry a verdict, indexed in `md/Backdoor_Audit_Verdicts.md`.

Every published HSWQ pack is quantized from a source model, and a backdoor written onto that source
survives quantization, so the audit is run on the source and on the pack, and the result is published
with the sha256 it applies to.

---

## 1. The question, stated so it can be answered

A backdoor is a branch: ordinary behaviour on ordinary input, attacker behaviour on chosen input. A
weight diff cannot establish either its presence or its absence. Two files that both reduce refusal
along one direction — one by dropping a single safety-direction projection, the other by adding a
rank-2 payload behind that projection — can produce similar-looking diffs and completely different
files.

The audit therefore does not ask "is this weight set unusual". It asks a question that has an answer:
*can this file branch on its input, by any of the shapes a file can use, and does any probe fire?*

---

## 2. The three branch shapes, and the measurement that closes each

A safetensors file can make the network branch on input in exactly three ways. The list is exhaustive
over file contents, not over attacker ingenuity.

| Shape | What it looks like | What closes it |
| :--- | :--- | :--- |
| **Added material** | a new tensor, bias, embedding row or adapter that is not in the declared base | full tensor census against the reference, including the zero-content census, with every key accounted for |
| **A second component behind the declared change** | something riding behind the edit the model openly makes — the abliteration direction carrying a rank-2 payload | the delta is projected onto its own principal directions; what the declared edit cannot account for is measured and named |
| **One component that reacts to a narrow input class** | the switch shape: a single direction that stays quiet on ordinary prompts | a trigger search over a candidate set, compared against the control spread, with a positive control on the instrument itself |

A poison trained diffusely across ordinary-looking weights is a training property, not a shape. What the
audit can do with it is the behavioural comparison and the rebuild test, and the reports say so rather
than implying a shape search covers it.

---

## 3. Verdict strength and coverage are defined, not implied

Every verdict carries both a strength and a coverage figure, because a verdict without them cannot be
read.

- **A** — the delta is fully accounted for at the weight level by the declared edit: every tensor of the
  artifact is compared against its reference, and the remainder is explained by the edit itself.
- **B** — the delta is dense and weight-level closure is not available, so the verdict rests on the
  behavioural probes.
- **C** — the weight-level audit covers part of the file only, and the behavioural probes carry the rest.

**Coverage** is the tensors the weight-level audit measured, over all tensors in the file. A verdict of
*no backdoor detected* therefore reads: none was detected in the artifact identified by the sha256 in
that row, by the tests that report documents, within the limits that report states. It is not a
probability. Wilson intervals quoted in reports are the uncertainty of a metric, never a probability of
absence.

---

## 4. Why the audit runs on the source, not only on the pack

The pack is INT8 — a small integer and a scale per weight — so a probe that needs 1e-6 resolution has
nothing to resolve. A direction written onto the source survives the rotation and the per-channel scale,
and a side channel (a bias, an embedding row, an added tensor) passes through unchanged. Removing the
direction from the source and re-quantizing reproduces the pack's behaviour, which makes auditing the
source the same audit performed one layer up, at the precision where the question can be answered.

The pack side is not skipped: exact re-quantization is the tool. The pack's INT8 codes are recomputed
from the source under the converter's own arithmetic, so a pack that carries anything the source does
not is detected as a code that cannot be reproduced.

---

## 5. The trigger search carries a measured instrument error

A behavioural pass is only worth the error rate of the instrument that produced it. The positive control
(`md/verdicts/Positive_Control.md`) runs the same probes on a clean base model and records **20/28 false
positives**. That number is published next to the results, not behind them: a pass means the trigger
ratio did not exceed the criterion, and the criterion is read against a control spread that is this wide.

Each report also states its own **LIMITS**: the candidate set size and how it was generated, the
positions probed, and the reference-class boundary — a defect already inside the comparison object's own
release is unreachable by definition.

## 7. Input integrity, and the replacement of a damaged copy

Before any number in the table is trusted, the artifacts are re-hashed on disk against their recorded
sha256 and byte counts.

- The artifacts then in the table were re-verified on 2026-10-28 and matched. Two of them had left the
  model directory during the work and were recovered with verified identity; the cause of that
  disappearance is recorded as unidentified rather than explained away.
- The first published `Qwen3-8B-abliterated-fp16.safetensors` was found to carry **206 all-zero tensors
  across 19 of 36 layers plus the final norm**. It was rebuilt from its declared upstream, and every one
  of the rebuilt file's **399 tensors now equals the reference BF16-to-FP16 cast** of
  `huihui-ai/Qwen3-8B-abliterated`, which is what makes the A verdict exhaustive rather than sampled.
  The index row states both the damaged and the rebuilt sha256, so a cached copy can be identified and
  replaced.

## 8. Tools, gates and records

- `audit/backdoor_audit.py` — the pack against its source: exact re-quantization, code-level reproduction,
  stored-float audit, container scan.
- `audit/source_audit.py` — the source itself: census, delta structure, merge proof, localisation
  ablation, trigger search.
- Gates over the reports: `audit/report_check.py` (structure and citation resolution),
  `audit/procedure_check.py` (the procedure's own steps present), `audit/check_cites.py` (every quoted
  number resolves to a real line in a real record), `audit/selftest.py`.
- `audit/check_hf_upload.py` — pre-flight for a model card before it is written to the Hub.
- **Records:** `md/verdicts/records/` holds every record a report cites — tensor censuses, rank
  structure, spectra, trigger candidate lists, per-candidate trigger values, generation texts with the
  hand labels read from them, and hash records of each file and its base. A claim without a record is a
  defect, not a judgement call.

## 10. Scope and limits

- The audit answers *"was a branch detected in this artifact, by these tests, within these limits"*. It
  does not answer *"this file is safe"*.
- **C** is not a pass of the same weight as **A**. SAM 3.1 is reported at C with 6 % weight coverage, and
  its verdict leans on behavioural probes whose instrument error is stated in §5.
- A behavioural probe set is finite. The candidate sets, their generation and the probe positions are in
  each report's LIMITS section precisely so that a reader can argue with them.
- The audit is run on the source and on the pack. A pack that reproduces its source exactly inherits the
  source's verdict and adds the code-level check; it does not get a stronger verdict than its source.
