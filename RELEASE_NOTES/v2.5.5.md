## 1. The direction, and why it cannot be reversed

The pipeline quantizes a pre-quantized INT8 pack into NVFP4. That is not a convenience: the INT8 pack already carries the rotation in its stamps (`convrot`, `convrot_groupsize`), so the builder can dequantize in the rotated domain and hand the **rotated** float to the NVFP4 quantizer, which stores it with `convrot: true` for the same group size.

Starting from FP16 would require re-deriving the rotation for every layer and re-validating the group size — the same arithmetic, with one more place for the rotation domain to disagree with the runtime. A domain mismatch is not a degraded approximation but a **different operation**: the weight is stored rotated and the runtime rotates the activation for the same group size, so the GEMM assumes both sides are in the rotated basis. Feed it a weight outside that basis and the multiply computes a different function of the input; the trajectory numbers then describe another model, not a quantization error. Section 3.2 of the guide states this with the numbers.

## 2. Additivity, and what the measurement can and cannot observe

Quantization error does not compose linearly: two layers perturbed together do not produce the sum of their individual errors once the intermediate state leaves the neighbourhood where the map is approximately linear. The reverse method buys additivity by measuring against an **exact anchor** — one NVFP4 layer substituted into the FP16 model, every other layer exact — so the recorded number is that layer's own contribution with no other error term present. Under that condition the impact behaves as a marginal cost, and sorting is meaningful.

What neither forward nor reverse selection can do is measure a **set**: the interaction term is not observed. The pipeline is designed so that the interaction stays small enough not to reorder the ranking, and the gate is what verifies it after the fact.

## 3. Why static weight statistics are not used

A conventional selector ranks layers by histogram MSE, kurtosis, outlier ratio or weight-space SVD. Those describe the **weight**, not the effect of the weight's error on the output, and they are blind to the amplification the sampler performs: the same relative weight error can leave the terminal latent almost unchanged or destroy it, depending on where the layer sits in the denoising chain. The reverse pipeline ranks by the terminal state the sampler actually produces, so the ordering already contains the amplification.

## 4. The measurement, the builder and the calibration

`Z_Image/diag_impact.py` holds every other layer pristine, replaces one NVFP4 layer, runs the same fixed trajectory, and records `rel_mse` against the pristine run; the criterion is the terminal state, not a single forward, because a single forward measures the layer where the sampler happens to call it once while the trajectory measures what the sampler experiences.

`Z_Image/gen_reverse_nvfp4.py` dequantizes the INT8 pack in its own rotated domain, quantizes each 2-D weight to NVFP4 with `comfy_kitchen`'s `TensorCoreNVFP4Layout`, and writes the pack with the rotation stamp and the group size the runtime will read.

`Z_Image/calib_input_scale_nvfp4.py` measures the activation amax on the real route so that

$$\text{input\_scale} = \frac{\max(\text{amax}, 10^{-12})}{448 \times 6} = \frac{\text{amax}}{2688}$$

**448** is the largest value an E4M3 global scale can represent and **6** the largest magnitude an E2M1 FP4 code can carry; their product bounds what one group can express, so the quotient puts the largest activation element exactly at that upper limit. The same quotient is the default `comfy_kitchen` computes for weights (`scale = amax / (F8_E4M3_MAX * F4_E2M1_MAX)`), so the activation scale and the weight scale follow one formula and the GEMM's two `tensor_scale` factors stay in a shared range.

## 5. The GEMM path

TC is armed by the presence of a calibrated `input_scale`; without it the loader keeps the stock GEMM and the online rotation. The mode is printed once per load. A pack that carries no `input_scale` gets a `ones(1)` placeholder with a flag, so the module can run on the parity path without pretending to be calibrated — the distinction between **calibrated** and **placeholder** is recorded, and a parity run is never reported as a TC run. NVFP4 GEMM needs compute capability ≥ 10.0; below it the run is a parity run whatever the flags say.

## 6. The deterministic 20-seed gate

| Item | Value |
| :--- | :--- |
| Seeds | `42, 1337, 7, 2024, 555, 43, 1458, 9, 2026, 777, 44, 1338, 8, 2028, 888, 46, 1587, 12, 2047, 222` — `--canonical-seeds`; the plain `--seeds` default is only five, so a run without the flag is not a gate run |
| Steps / resolution | 12 / 1024 × 1024 |
| CFG / sampler / scheduler | 2.5 / euler / simple |
| Attention | SA2 (`--attention sage2`), applied to the quantized model only; the FP16 baseline keeps baseline attention |
| GEMM | TC (`--tc`) on the calibrated hybrid; `--parity` forces the other path |

A seed is the only source of variation, so the comparison is paired seed by seed. The verdicts are ordered: `bifurcated @step N` when one step's cosine drops by more than 0.05, `same-image` when the final cosine is at least 0.98 and no step crossed that threshold, `drifted (different image)` otherwise. The bifurcation test runs first, so a seed whose final cosine is high but which jumped attractors is never reported as `same-image`.

**PASS = mean final cosine ≥ 0.95 AND 0/20 bifurcated, measured in SA2 + TC.** Both conditions are required: either alone admits configurations that fail in the other.

What the table supports:

- **Bifurcation elimination.** 0/20 on every checkpoint — zero bifurcated seeds in 220 runs — against four native bifurcated seeds spread over three checkpoints. This is the strongest statement in the table because the count is discrete.
- **Mean separation.** The hybrid's mean sits 0.02074 to 0.05976 above native on every checkpoint, and no checkpoint inverts the ordering.
- **Latent MSE.** Mean final latent MSE falls by roughly 40–60 % relative to native across the set (for example `moodyWildMixZIBZID_v02`: 0.8584 against 1.6914).

The hybrid's per-checkpoint minima therefore span 0.79572 to 0.94122; a mean hides that tail, which is why the minimum is listed per checkpoint in the benchmark report.

`same-image` counts are low across the set — **60 of 220 runs (27.3 %)** — the other 160 are `drifted`, and none are bifurcated. A 4-bit DiT at these settings drifts, and the pipeline's claim is that it drifts **without** crossing a discontinuity, not that it is indistinguishable.

**What these numbers are not.** They are not an image-quality claim. A trajectory cosine measures whether two runs produced the same latent; two noise fields would also correlate highly. Picture judgement is made by decoding and looking, never from this table.

## 8. Finding $K$

$K$ is checkpoint-specific and the quality surface is not a single cliff: which seeds fail changes with $K$, and quality can recover and fail again. The procedure is a sequential search — start at $K = 90$, run the full chain (build → calibrate → gate); if it passes, raise $K$ by 10 and repeat, and the answer is the **largest $K$ that still passes**; if it fails, lower by 10 until it passes; any $K$ with a single bifurcated seed is rejected even when the mean passes; near an ambiguous boundary, sweep $K \pm 1$–$2$, because passing islands exist.

Reference curve for one checkpoint (`moodyProMix_collectorsEdition`, 20 seeds × 12 steps, measured before the SA2 option existed and kept as the TC-versus-parity ordering only, then re-measured in SA2 + TC before shipping):

| Pack | $K$ | mean | min | max | same-image | bifurcated | GEMM |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | :--- |
| nv90 | 90 | 0.95852 | 0.82504 | 0.98816 | 5/20 | 0/20 | TC (W4A4) |
| **nv100 (adopted)** | **100** | **0.96033** | **0.87123** | **0.98680** | **4/20** | **0/20** | **TC (W4A4)** |
| native | 180 | 0.91079 | 0.59021 | 0.96337 | 0/20 | **1/20** | PARITY (W4A16) |

Raising $K$ from 90 to 100 bought +0.0018 mean while the minimum rose +0.046, and the next step is where failures reappear. $K$ is chosen where the mean stops paying for the extra bytes, with the minimum — the tail a user will hit — part of the decision rather than a footnote.

## 9. Operational contracts

| Contract | Why |
| :--- | :--- |
| Never mix ranking sources across checkpoints | The impact JSON is a property of the weights; a ranking measured elsewhere silently converts the wrong layers |
| Never build the hybrid from FP16 | The rotation domain comes from the INT8 pack's stamps; re-deriving it adds a second place for the domain to disagree |
| Never measure with a proxy quantizer | The E4M3-per-256 proxy understates the error about 13× and flattens the ranking |
| Never force TC on an uncalibrated pack | The activation scale is a placeholder and the measured result collapses |
| Never report a TC number measured off a Blackwell GPU | NVFP4 GEMM needs compute capability ≥ 10.0; below it the run is a parity run whatever the flags say |
| Never judge a pack from a parity run when the target is TC | Different computation, different number; state the mode with the result |
| Never report a mean without the bifurcation count | A high mean can hide a single discontinuous seed, which is a different picture |
| Never call trajectory cosine an image-quality measure | It compares latents; identical noise correlates at 0.99 |
| Never edit `ComfyUI-master/` | It is the bundled runtime reference; the pipeline patches at runtime only |
| One process at a time | The measurement, the conversion and the gate each hold a full DiT; concurrent runs exhaust VRAM |

## 10. Reproduction

The guide's section 15 carries the checklist end to end: pin the source and its SHA, run `diag_impact.py` for the checkpoint's own ranking, run `gen_reverse_nvfp4.py` with that ranking, calibrate `input_scale` on the real route, then run the gate with `--canonical-seeds --steps 12 --attention sage2 --tc` and read the verdict from the bifurcation count as well as the mean. Every step names the file it writes, and every number in section 7 of this note came from that chain.

**Limits stated in the document itself:** no criterion here is globally optimal because every method measures one layer at a time while tens are quantized together; single-layer contributions are not additive, so two criteria that disagree can reach the same score; the ranking is checkpoint-specific and must be re-measured for every model; and the acceptance uses fixed seeds and prompts, so it compares packs rather than claiming absolute quality.
