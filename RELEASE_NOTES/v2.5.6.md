## 1. The direction, and why FP16 cannot be the base

The pipeline converts a pack that is already quantized: the input is the complete ConvRot INT8 pack, and the builder moves the $K$ lowest-impact layers to ConvRot W4A8. The INT8 pack already carries the rotation in its stamps (`convrot`, `convrot_groupsize`), so the builder dequantizes in the rotated domain, un-rotates once to the physical basis, and hands that float to the W4A8 packer — which rotates inside, because `comfy_kitchen.quantize_w4a8_int8_weight` is the ConvRot-aware entry point.

Starting from FP16 would require re-deriving the rotation for every layer and re-validating the group size — the same arithmetic with one more place for the rotation domain to disagree with the runtime. A domain mismatch is not a degraded approximation but a **different operation**: the weight is stored rotated and the runtime rotates the activation for the same group size, so the GEMM assumes both sides are in the rotated basis. Feed it a weight outside that basis and the multiply computes a different function of the input; the trajectory numbers then describe another model, not a quantization error. Section 3.2 of the guide states this with the numbers.

The same rule applies one level down: the source weights are rotated, and the W4A8 packer rotates internally, so the converter un-rotates first. A double rotation yields noise, not a small error.

## 2. Additivity, and what the measurement can and cannot observe

The measurement substitutes one ConvRot INT8 layer into the **unquantized FP16 base** and leaves every other layer exact, so the recorded number is that layer's own error contribution with no other error term present. Under that condition the impact behaves as a marginal cost, and sorting is meaningful. What neither forward nor reverse selection can do is measure a **set**: the interaction term is not observed. The pipeline is designed so that the interaction stays small enough not to reorder the ranking, and the gate is what verifies it after the fact.

A conventional selector ranks layers by histogram MSE, kurtosis, outlier ratio or weight-space SVD. Those describe the **weight**, not the effect of the weight's error on the output, and they are blind to the amplification the sampler performs: the same relative weight error can leave the trajectory almost unchanged or destroy it, depending on where the layer sits in the denoising chain. The reverse pipeline ranks by the latent states the sampler actually produces, so the ordering already contains the amplification. It also answers a question the other rankings do not ask: the layers that move to W4A8 leave a pack whose error already includes the INT8 transition, so the ranking must identify which layer can lose the next four bits.

## 3. The measurement, and the reconstruction it injects

`Flux1/diag_impact.py` replaces one layer at a time with its **true ConvRot INT8 reconstruction in the original basis**:

$$W_q = \operatorname{dequant}_{\text{INT8}}\!\left(W H^\top\right) H$$

The deployed pack stores the weight rotated and the kernel rotates the activation online, so the layer's effective weight is `dequant_rotated @ H`, which is `W` up to the INT8 reconstruction error. Injecting that equivalent weight into the plain FP16 module reproduces exactly the layer the pack ships. The docstring records the measurement that fixes this choice: on a synthetic 64×512 weight, `cos(W_q, W) = 0.999973` with the un-rotation and `0.072427` without it. Injecting the rotated tensor therefore measures a **basis mismatch**, not the quantization.

The trajectory is the **production sampler** (`comfy.sample.sample`), not a hand-rolled schedule, so the measured ranking follows exactly the trajectory the gate measures. FLUX needs both text encoders in one `load_clip` call with `CLIPType.FLUX`; the pipeline loads `t5xxl` and `clip_l` on CPU, encodes the conditioning, and unloads the encoders before the DiT runs, so the whole GPU belongs to the diffusion model. The metric is the **mean over the recorded steps**, not the terminal state alone: a layer whose error appears mid-trajectory and is partly absorbed later still contributes to the score. Injection is restored in `finally`, so one failed trajectory cannot leak into the next layer's measurement.

The measurement has a stated boundary: the substituted weight is the FP16 weight round-tripped through ConvRot INT8, while the shipped pack carries that reconstruction round-tripped through W4A8. The ranking therefore measures the **INT8** transition; the hybrid's total error is that transition plus the W4A8 transition, and the gate measures the total.

## 4. The builder, and what a W4A8 layer stores

`Flux1/gen_reverse_w4a8.py` sorts the impact ascending and takes the first $K$. No weighting, no threshold, no per-block quota: one scalar per layer, one cut. Each converted layer writes four sidecars next to the stamp:

| Key | dtype | Shape | Meaning |
| :--- | :--- | :--- | :--- |
| `.weight` | int8 | `[N, K/2]` | nibble-packed 4-bit codes, low nibble = even column |
| `.weight_s_rel` | fp8_e4m3 | `[N, K/16]` | per-group (16) scale |
| `.weight_s_channel` | float32 | `[N]` | per-out-channel scale |
| `.weight_codebook` | float32 | `[16]` | Lloyd-Max table |
| `.comfy_quant` | uint8 JSON | — | `{"format":"asym_w4a8_int8","group_size":16,"convrot_groupsize":256}` |

`orig_shape` is not written in this stamp because the module owns it: `MixedPrecisionOps.Linear.__init__` sets `_orig_shape = (out_features, in_features)`, and the grouped-int8 load path verifies `weight.shape[1] * 8 == _orig_shape[1] * bits`, raising with the layer name, the packed width and K when they disagree. A pack whose packed width does not match its declared K therefore fails at load instead of running with a mis-sized weight.

The same stamp is recorded under the prefixed key and under the stripped key in `_quantization_metadata`, so a hybrid pack can itself be used as the layer-list source for a later build. Everything the builder does not touch is copied through unchanged: a hybrid pack is the INT8 pack with a subset of layers re-encoded, not a rebuild from scratch.

## 5. Card 1 bias correction, and the reference it must use

A 4-bit weight carries a systematic error, and a Linear layer turns that error into a constant offset in its output. Card 1 folds the offset back into the layer bias: `bias -= (W_q - W) · E[x]`. The pack stores `bias - delta`; the runtime adds no extra work.

The reference matters. The reverse converter starts from the INT8 pack, so an INT8-based reference covers only the INT8 → W4A8 step, while the pack carries both transitions. Passing `--fp16` makes the converter read the original weight and bias from that file. The measurement recorded in the how-to is **bias ON 0.95218 against OFF 0.953** — the INT8-referenced correction scores below leaving the bias alone, which is why the option is opt-in and the delta has to be measured against the FP16 weight.

The correction is measured on a real calibration run: the DiT is loaded through ComfyUI, both text encoders build the contexts, and a DualMonitor records the per-layer `E[x]` over `--num_calib_samples 32` × `--num_inference_steps 25` with `--latent_size 32`, `guidance = 3.5`, seed `42 + i` and the timestep weight `1 - t`. The hooks match on layer shape attributes (`in_features` / `in_channels`), not on the PyTorch class — `MixedPrecisionOps.Linear` has **no `weight` attribute at construction**, so an `isinstance(module, torch.nn.Linear)` filter matched nothing on an INT8 pack and collected zero activations. The run **aborts instead of saving** when zero layers were corrected, so a pack labelled bias-corrected always carries a real correction. Only the layers lifted to W4A8 are touched; the INT8-kept layers keep their bias byte for byte, and the INT8 pack must stay un-corrected so the reverse build does not subtract a second delta.

## 6. The execution paths

| Mode | Computation |
| :--- | :--- |
| Core grouped-int8 GEMM (`asym_w4a8_int8`) | `comfy/ops.py` reads the pack sidecars, checks the packed width against the layer's declared K and builds `AsymW4A8Int8Layout`; the GEMM multiplies 4-bit weights by INT8 activations |
| INT8-kept layers (`int8_tensorwise` + `convrot`) | The ConvRot INT8 stack arms each layer from its own stamp; the activation is rotated online for the layer's group size |
| LoRA residual (loader only) | The stock GEMM runs on the untouched pack and the factorised LoRA terms are added after it, in the original basis |

The pack itself needs no dedicated loader: core declares and decodes `asym_w4a8_int8`, so **Load Diffusion Model** / **UNetLoader** loads the file. A hybrid arms both paths. A LoRA forces the loader: a 4-bit weight has 16 code levels, a LoRA delta of roughly 0.1–0.8 % of amax is below half a code step, so baking the delta into the packed weight rounds it away — the loader leaves the pack untouched and adds `((x @ dn^T) @ up^T) * scale` after the stock GEMM, with the factors kept low-rank so no dense `[out, in]` matrix is materialised.

**Three keys must never be packed.** ComfyUI's FLUX detector reads `shape[1]` of `img_in`, `txt_in` and `vector_in.in_layer` to size the architecture; packing any of them halves the K the detector reads. The measured artifact shows the boundary modules are INT8 in the pack — `img_in.weight` is `int8_tensorwise` with 196,608 bytes — because the INT8 conversion that produced the input pack already quantized them. The exclusion that matters for this pipeline is the exclusion from the **W4A8** re-encoding.

The measured hybrid quantizes **314 layers** in total: 170 as `asym_w4a8_int8` and 144 as `int8_tensorwise`, out of the 1,748 tensors in the file.

## 7. The deterministic 25-seed gate, and the protocol it now records

| Item | Value |
| :--- | :--- |
| Seeds | `42, 137, 849, 2024, 7391, 18429, 53082, 149206, 382715, 826401, 1938502, 4710928, 8391642, 15820493, 36192847, 71058294, 128491703, 285039184, 491730285, 762019483, 938174026, 1409285713, 2683910547, 3851729406, 4195820371` — the comparator's default |
| Steps / resolution / cfg | 12 / 1024 × 1024 / 1.0 (script defaults) |
| Sampler / scheduler | euler / simple |
| Quantized-side argument | `--w4a8` (aliases `--int8` / `--fp8` / `--quant`) |

The verdicts are ordered: `bifurcated @step N` when one step's cosine drops by more than 0.05, `same-image` when the final cosine is at least 0.98 and no step crossed that threshold, `drifted (different image)` otherwise. The bifurcation test runs first, so a seed whose final cosine is high but which jumped attractors is never reported as `same-image`.

**PASS = mean final cosine ≥ 0.95 AND 0/25 bifurcated.** Both conditions are required; either one alone admits configurations that fail in the other.

This release also fixes a gap in the instrument itself: the comparator now prints a `PROTOCOL` block before any model is loaded, carrying the two model paths with their file sizes, both text-encoder paths, the ComfyUI root, the seed list, the step count, the resolution, the cfg, the sampler, the scheduler and the prompt. A score log therefore states the conditions it was measured under, and a log file can be compared with another one without guessing which default was in force. The 25-seed run tabulated below predates that block, so its own resolution, step count, cfg, sampler and scheduler are not recoverable from its log file; what the log does carry is the seed list, the per-seed cosines and MSEs, the verdicts and the wall times.

## 8. Measured results, one checkpoint × 25 seeds

| Model | Hybrid $K$ | HSWQ mean | Native mean | Δ | HSWQ bifurcated | Native bifurcated |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| F1D_unlockV3.1off | 170 | **0.95383** | 0.93006 | +0.02377 | **0/25** | 1/25 |

What the table supports:

- **Bifurcation elimination.** 0/25 for the hybrid against 1/25 for the native pack, on the same seed set and the same trajectory configuration. The single native bifurcated seed is `762019483`; the hybrid stays coherent on that seed.
- **Mean cosine separation.** +0.02377 mean final cosine, with the minimum also higher (0.80155 against 0.78136) and the maximum higher (0.99135 against 0.98410). The ordering is not carried by a few easy seeds.
- **Latent MSE.** Mean final latent MSE 1.1161 against 1.7803, about 37 % lower error.
- **Same-image count.** 11/25 for the hybrid against 4/25 for the native pack. The remaining hybrid seeds are `drifted`, none bifurcated: at these settings a 4-bit DiT drifts, and the pipeline's claim is that it drifts **without** crossing a discontinuity.
- **Speed.** 2.97 s per seed for the hybrid against 4.71 s for the FP16 reference, +37.0 %, and 2.94 s for the native W4A8 pack — the two 4-bit arms cost the same, so the fidelity gain is not paid for in speed.

**What these numbers are not.** They are not an image-quality claim. A trajectory cosine measures whether two runs produced the same latent; two noise fields would also correlate highly. Picture judgement is made by decoding and looking, never from this table.

The hybrid sits between the two formats it mixes: it gives up 2,927,285,632 bytes against the all-INT8 pack (−24.6 %) and keeps 2,265,811,568 bytes over the all-W4A8 pack. Inside the file, the 170 W4A8 layers occupy 3,769,698,944 bytes (3,345,481,728 of nibble-packed weight, 418,185,216 of fp8 group scales, 6,021,120 of fp32 channel scales and 10,880 of codebook — 170 × 64 B), the 144 INT8-kept layers occupy 5,213,602,048 bytes (5,207,359,488 of int8 weight and 6,242,560 of fp32 channel scales), and the non-quantized remainder is 38,912 bytes of bf16, out of 1,748 tensors in the file. The 170 converted layers carry a **43.7 %** weight reduction against the same layers as INT8. The 144 INT8-kept layers are byte-for-byte identical to the same layers in the all-INT8 pack of the same architecture — measured difference 0 bytes over all 144.

The all-W4A8 size was built and measured with the native routing rule (313 layers to W4A8, 1 layer kept ConvRot INT8). The weight values differ from a native conversion (INT8 source, not FP16 source); the storage sizes are a property of the layer shapes, which is what is measured.

## 10. Finding $K$, and why the sweep is measured

$K$ is checkpoint-specific and the quality surface is not a single cliff: which seeds fail changes with $K$, and quality can recover and fail again. The procedure is a sequential search — start from a $K$ that leaves a visible INT8 remainder, run the full chain, raise $K$ while the gate passes and the answer is the **largest $K$ that still passes**, lower until it passes if it fails, reject any $K$ with a single bifurcated seed even when the mean passes, and sweep $K \pm 1$–$2$ near an ambiguous boundary, because passing islands exist.

**The size side of the curve is measured, and it is not linear in $K$.** Each W4A8 layer replaces an INT8 layer of the same shape, and the saving is fixed by that shape: $N \cdot K$ bytes of INT8 weight become $N \cdot K/2$ nibble-packed bytes plus $N \cdot K/16$ fp8 group scales plus $N$ fp32 channel scales and a 16-entry codebook, so the saving is $\frac{7}{16}NK + 4N + 64$ bytes. Measured over the 170 layers of the r170 pack, the saving ranges from **4,128,704** bytes (`double_blocks.1.img_attn.proj`, 3072×1536) to **28,901,312** bytes (`single_blocks.9.linear1`, 21504×1536), mean **17,219,327** — a factor of seven between the smallest and the largest layer. The byte cost of the next $K$ therefore depends on which layer the ranking puts next, and the pack at each $K$ is built and its size read from the file.

**The quality side of the curve needs the FP16 source.** The gate compares the pack against the FP16 DiT, so a $K$ curve is a trajectory measurement. `benchmark/run_flux1_w4a8_k_sweep.ps1` runs the whole chain for a list of $K$ values — build the pack, run the 25-seed gate, record the file size and the gate numbers — and `benchmark/build_flux1_w4a8_sweep_md.py` renders the rows as the benchmark table. The sweep writes one CSV row per $K$ and one markdown table, and the comparator's own `PROTOCOL` block lands in each per-$K$ log, so a swept curve carries its conditions as well as its numbers.

## 11. Operational contracts

| Contract | Why |
| :--- | :--- |
| Never mix ranking sources across checkpoints | The impact JSON is a property of the weights; a ranking measured elsewhere silently converts the wrong layers |
| Never build the hybrid from FP16 | The rotation domain comes from the INT8 pack's stamps; re-deriving it adds a second place for the domain to disagree |
| Never inject in the rotated basis | Injecting `W_rot` measures a basis mismatch: 0.072427 cosine against 0.999973 for the un-rotated reconstruction |
| Never double-rotate in the builder | The W4A8 packer rotates internally; handing it the rotated INT8 weight yields noise, not a small error |
| Never pack `img_in` / `txt_in` / `vector_in.in_layer` | The FLUX detector reads their `shape[1]`; packing halves the K it reads and the model is mis-sized |
| Never bias-correct an already-corrected pack | The reverse converter starts from the INT8 pack; a corrected input subtracts a second delta |
| Never reference the INT8 dequant for the Card 1 delta | It covers only the INT8 → W4A8 step; the measured score with that reference is 0.95218 against 0.953 for leaving the bias alone |
| Never report a mean without the bifurcation count | A high mean can hide a single discontinuous seed, which is a different picture |
| Never call trajectory cosine an image-quality measure | It compares latents; identical noise correlates at 0.99 |
| Never edit `ComfyUI-master/` | It is the bundled runtime reference; the pipeline patches at runtime only |
| One process at a time | The measurement, the conversion and the gate each hold a full 12B-class DiT; concurrent runs exhaust VRAM |
| Never hand-build the W4A8 sidecars | The layout class the runtime reads is the one that must write the pack; hand-built names drift from the reader |

## 12. Reproduction

The guide's section 15 carries the checklist end to end: build the complete ConvRot INT8 pack, measure the checkpoint's own ranking with both text encoders, build the hybrid at the chosen $K$, optionally correct the bias with `--fp16`, then run the gate and read the verdict from the bifurcation count as well as the mean. Every step names the file it writes, and every number in sections 8 and 9 of this note came from that chain or from the pack the chain produced.

**Limits stated in the document itself:** no criterion here is globally optimal because every method measures one layer at a time while tens are quantized together; single-layer contributions are not additive, so two criteria that disagree can reach the same score; the ranking is checkpoint-specific and must be re-measured for every model; the acceptance uses fixed seeds and prompts, so it compares packs rather than claiming absolute quality; and the 2026-11-21 run's resolution, step count, cfg, sampler and scheduler are not recoverable from its score log, because the comparator began printing its protocol after that run.
