## Overview

v2.5.2 re-verifies the ControlNet and model-patch packs on the instrument that built each of them, and re-quantizes the lineart ControlNet pack under the trajectory-impact protection. The weight-level comparison now runs each family's own `rotate_weight`, `quant_rowwise` and group-size function instead of a borrowed rotation, so the replay agrees with the pack value for value: the five model-patch packs close with **0 differing INT8 values**, a **largest relative scale difference of 0.0** and a **bit-identical float side**. The lineart pack is rebuilt from its publisher's checkpoint with a protection set measured on that checkpoint (400 modules swept, 15 layers above the drift threshold kept in FP16) and is published as the twelfth file on the model card.

## 1. The instrument rule: the replay runs on the builder that made the pack

A weight-level closure is only as good as the arithmetic it replays. When the replay is performed with a rotation and a quantisation borrowed from another tool, the same pack reports a residue that is not a property of the pack: the `qwen_image_canny_diffsynth_controlnet_hswq_convrot_int8.safetensors` pack reports **948 INT8 values differing by one step at a .5 rounding boundary** and a **5.62e-07 relative scale difference** under a borrowed rotation, while under its own family's `rotate_weight`, `quant_rowwise` and group-size function the same pack reports **0 differing values** and **0.0**. The same holds for the other four model-patch packs (883, 539, 138 and 118 borrowed-instrument codes against 0 under the builder's own functions).

The rule the procedure now states: **the replay runs on the instrument that produced the artifact.** For the model-patch family that is the builder of each family -

| family | builder used by the replay | record |
| :--- | :--- | :--- |
| Qwen-Image diffsynth model patch | `clip_convert/convert_qwen_image_diffsynth_patch_impact_convrot_int8.py` | `records/qwen_diffsynth_canny_pack_audit.json` |
| Z-Image Fun ControlNet model patch | `Z_Image/build_zimage_modelpatch_convrot_int8.py` | `records/zimage_union21_pack_audit.json` |
| SDXL ControlNet | `clip_convert/convert_controlnet_convrot_int8.py` | `records/noobai_hswq_pack_audit.json` |

## 4. The loader route, measured instead of assumed

A ConvRot INT8 pack only runs its INT8 path on a loader that builds it with `MixedPrecisionOps`, so the loader is part of the artifact's behaviour and is measured rather than described. On the SDXL ControlNet files, in one two-step forward:

| pack | HSWQ ControlNet Loader | ComfyUI's own ControlNet loader |
| :--- | :--- | :--- |
| `CN-anytest4_illustrious2_A_hswq_convrot_int8.safetensors` | 326 of 326 declared layers applied, 652 INT8 calls | loads the file, 0 INT8 calls |
| `CN-anytest4_illustrious2_B_hswq_convrot_int8.safetensors` | 327 of 327 declared layers applied, 654 INT8 calls | loads the file, 0 INT8 calls |
| `controlnet-union-pro-max-sdxl-1.0_hswq_convrot_int8.safetensors` | 325 of 328 declared layers applied, 650 INT8 calls | loads the file, 0 INT8 calls |

The model-patch side is measured the same way: the HSWQ Model Patch Loader applies 120 of 120 declared layers on the diffsynth packs and 38 of 38 on the Z-Image packs, and the corresponding forwards issue 966 and 38 INT8 calls. The ComfyUI-side probe was completed for the SDXL ControlNet files only; the FLUX and Qwen-Image ControlNet rows of `records/card_loader_route_probe.json` carry the harness error that stopped that side of the comparison.

## 5. The model card

The card now lists twelve files, the re-quantized lineart pack among them, and its usage section names the loader each file type needs: the ControlNet files load with the **HSWQ ControlNet Loader** node, the model-patch files with the **HSWQ Model Patch Loader** node followed by `ZImageFunControlnet` or `QwenImageDiffsynthControlnet`. The card's per-file size and sha256 columns were checked against the published objects.
