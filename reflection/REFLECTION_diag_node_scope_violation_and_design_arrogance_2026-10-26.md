## 第6章 罪 5 — 入力が空のときのフォールバック分岐を勝手に作った

### 何をしたか

当方は `_measure_sd15` の中で、以下のような分岐を書きました。

```python
argv = _sd15_argv(base_path, out_path, steps, seeds or _SD15_SEEDS,
                  metric or _SD15_METRIC, comfy_path)
```

つまり「入力が空なら定数にフォールバックする」という処理でございます。

### 本質

この一行が、**送信される値を当方が制御する構造**を作りました。入力欄を空にすれば当方の定数が使われ、値を入れればその値が使われる。どちらが実際に送られたかは、利用者には見えません。

指示外の分岐を足すと、こうして挙動が読めなくなります。「空のときは既定値」という一見親切な設計が、実は**暗黙の動作**を生み、検証を困難にします。測定条件が変わりうる箇所を、当方が勝手に作りました。

### 実測した事実

確定版では、値は定数から直接渡されます。分岐はございません。

```python
argv = _sd15_argv(base_path, out_path, steps, _SD15_SEEDS, _SD15_METRIC, comfy_path)
```

実際に構築される argv を実測した結果でございます。

```
--steps   25
--seeds   42,137
--metric  relmse
```

`--seeds` の値は `'42,137'`、`--metric` の値は `'relmse'` で、スクリプトの既定値と一致しております。

### 正しい動作

分岐を作らない。定数を直接渡す。値が一意に定まる状態を保つ。

```python
comfy_path = os.path.join(_REPO_ROOT, _COMFY_PATH)
if not os.path.isdir(os.path.join(comfy_path, "comfy")):
    raise ValueError(
        f"the ComfyUI root is missing (no comfy/ inside): {comfy_path!r}"
    )
```

### 正しい動作

`--comfy` は常に明示的に送る。存在チェックも維持する。既定値の有無を、コードで確認してから設計する。
